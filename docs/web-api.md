# Web API reference

This is a reference for the HTTP and WebSocket API served by the hub's web UI
(`components/webui/`). It is generated by reading the route tables and handlers;
where a request or response shape is obvious from the code, the key fields are
listed. Anything not listed should be read from the handler source.

Unless noted otherwise, everything below applies to the **HA profile**.
Endpoints that exist only in the Direct profile are listed in
[Direct-profile endpoints](#direct-profile-endpoints), and HA-only endpoints
that the Direct profile drops are listed there too.

## Basics

- **Ports.** Port 80 serves the web UI, the REST API under `/api/v1/`, the
  WebSocket at `/ws`, and the OTBR REST API. Port 8081 is a second, smaller
  HTTP server that serves only the OTBR REST routes (the standard OTBR port).
- **Format.** JSON in and out, `Content-Type: application/json; charset=utf-8`.
  A few OTBR routes return `text/plain`, as upstream OTBR does.
- **Errors.** Non-2xx responses carry `{"error":"<code>"}`, for example
  `{"error":"login_required"}` with 401. Status codes in use: 400, 401, 403,
  404, 405, 406, 409, 413, 421, 429, 500, 501, 503.
- **Single request worker.** All port-80 requests are handled by one HTTP task.
  Endpoints that block (energy/beacon scans, the cloud update check) hold up
  every other request until they finish. Long jobs return `202 Accepted` and
  are polled through a status endpoint.
- **Unknown paths.** Unknown `/api*` paths return 404 JSON. Other unknown paths
  fall back to the web UI's `index.html` (SPA routing). Static files are stored
  gzip-compressed only; a client that refuses gzip gets 406.

## Authentication

### Admin password and sessions

The hub has a single admin password (4-63 bytes, valid UTF-8, stored as a
SHA-256 hash). **While no password is set, every endpoint is reachable without
credentials**; this is the factory state, so that the first user can get in
and set one.

Once a password is set, a request is authenticated by any of:

1. **Session cookie** `token=<32 hex chars>` (set by login;
   `HttpOnly; SameSite=Strict; Path=/; Max-Age=86400`).
2. **Bearer token**: `Authorization: Bearer <token>` with the same session token.
3. **HTTP Basic**: `Authorization: Basic base64(<any user>:<admin password>)`.
   Only the password half is checked.

Session details (`auth.c`):

- Tokens are 16 random bytes in hex. Up to 4 sessions exist at once; when the
  table is full the least recently used one is evicted.
- A session expires 24 hours after it was created, regardless of activity.
- Changing the password invalidates every other session (the session that
  made the change is kept).
- Token comparison is constant-time.

Login flow:

```http
POST /api/v1/auth/login
Content-Type: application/json

{"password": "<admin password>"}
```

Response: `{"status":"ok","token":"<token>"}` plus the `Set-Cookie` header.
With no password set, the response is `{"status":"no_password","token":"..."}`.

**Throttling.** After 5 consecutive failed password checks (login or Basic),
password checks are locked for 2, 4, 8, 16, then 32 s (capped). During the
lock even a correct password is refused (login returns 429
`too_many_attempts`). The counter is global, not per client. Session tokens
are not throttled.

### Read-only endpoints that stay open

A few read endpoints use a weaker check (`AUTH_REQUIRED_UNLESS_OPEN`): they are
readable without credentials **unless** the REST lock is turned on with
`POST /api/v1/otbr/auth {"enabled":true}` (which requires an admin password).
These are marked **open** in the tables. They expose roughly what the hub
already announces over mDNS, and they let integrations discover the hub
before asking for a password.

### Cross-origin guard

Every POST, PUT and DELETE endpoint, the OTBR routes, and several sensitive
reads run a cross-origin check **before** authentication (`cross_origin.c`). It answers "which page made
the browser send this request", independent of who the user is:

| Check | Rejects with | Rule |
|---|---|---|
| `Host` | 421 `{"error":"unknown_host","use":"http://<hub-ip>/"}` | Host must be an IP literal, `localhost`, the hub's hostname alone or followed by one of `.local`, `.lan`, `.home`, `.home.arpa`, `.internal`, `.localdomain`, `.fritz.box`, or the extra host name configured with `/api/v1/net/access-host`. Blocks DNS rebinding. The `use` field gives the address the request arrived on. |
| `Sec-Fetch-Site` | 403 `cross_origin` | If present, must be `same-origin` or `none`. |
| `Origin` | 403 `cross_origin` | If present, must equal `http://` + the `Host` header (including the port). |

A header that is **absent** passes, so non-browser clients (curl, Home
Assistant, scripts) are unaffected. A header that is present but too long is
rejected. Running the guard before authentication means a cross-site request
never reaches the password check and never counts toward throttling.

The guard is applied per handler, not globally, so that `/api/actions` keeps
returning 404 (Home Assistant's OTBR client probes it and accepts only 200 or 404).

### Table legend

- **Auth**: `none` = no credential check; `open` = see above; `admin` = admin
  session / Bearer / Basic required (passes while no password is set);
  `otbr` = OTBR gate (see [OTBR REST API](#otbr-rest-api)).
- **Guard**: `yes` = cross-origin guard runs first.

| Path | Auth | Description |

### OTBR authentication

The OTBR routes run the cross-origin guard and then an OTBR-specific gate. By
default the gate is **open**, because Home Assistant's OTBR integration sends
no credentials of its own. Two opt-in settings close it:

1. **REST lock** (`POST /api/v1/otbr/auth {"enabled":true}`): the OTBR routes
   (and the `open` endpoints elsewhere) require normal admin authentication.
2. **OTBR token** (`POST /api/v1/otbr/token {"action":"generate"}`): a random
   128-bit token valid only on the OTBR routes, sent as the HTTP Basic password
   (the user name is ignored). The generated URL has the form
   `http://otbr:<token>@<hub-ip>:8081`, which can be entered as the OTBR URL in
   Home Assistant. While a token is set:
   - Basic credentials on these routes are compared with the token only; the
     admin password is not accepted there, and failures do not count toward
     the login throttle.
   - Requests without Basic credentials fall back to normal authentication,
     so the web UI's session still works.

`/api/v1/diag/thread` is registered alongside the OTBR routes (so it is also on
port 8081) but always requires admin authentication.

| POST | `/api/v1/muse/pair/cancel` | Cancel pairing (only during a pairing boot) |
| POST | `/api/v1/muse/unpair` | `{"confirm":"UNPAIR"}`: drop the local Muse credentials (the device should also be removed in the Muse app) |
| POST | `/api/v1/muse/test_push` | Queue a test notification (202; 409 if not online) |
| GET | `/api/v1/muse/audit` | Audit log of commands and settings changes (`limit`, newest first) |

### Other Direct-profile differences

- Added: `POST /api/v1/system/reboot` (restart; 409 while an update is running).
- `GET /api/v1/status` adds `"profile":"direct"`, `"wifi":"absent"`, and (with
  Muse) `muse_state`, `blew_state`, `muse_link`.
- `GET /api/v1/zigbee/status` includes the Zigbee host's state.
  `POST /api/v1/zigbee/restart` performs a soft restart of the Zigbee host
  session (409 if it does not currently own the UART).
- `POST /api/v1/diag/safemode/exit` accepts `{"muse_off":true}` to keep Muse
  disabled on the next boot.
- Not present: `/api/v1/wifi/*`, `/api/v1/network/softap`, `/api/v1/diag/wifi_probe`,
  `/api/v1/mode`, `/api/v1/whitelist`, `/api/v1/zigbee/clients/disconnect`, and
  all coordinator-compatibility endpoints (`/api2/*`, `/ha_info`, `/ha_sensors`,
  `/settings/saveParams`).
- OTBR REST routes are present as in the HA profile.

### Pairing boot

While the hub is in its isolated Muse pairing boot, only these are registered:
the auth endpoints, the Muse endpoints above, a reduced
`GET /api/v1/status` (no authentication; reports `"mode":"muse_pair"`), and a
small pairing-progress page served for every other `GET` path. Port 8081 is not
started.
